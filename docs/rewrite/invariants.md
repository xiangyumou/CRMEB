# Invariant parity

Every line of `tests/regression/cases.md` appears here once. The owning stream fills in "New test ID" (`<file>::<test name>`) and sets State to `ported`, or to `retired` / `dropped` with a reason in the Invariant cell. Stream K fails the build while any row is `unmapped`. The risk matrix (`tests/regression/risk-matrix.md`) adds rows that were "new" or "thin" there; owners append those under their section.

Rows whose section owner is "dropped" need no test; the orchestrator closes them at G0.

when stock moves. What _does_ the moving is `catalog.stock.ts`, which implements
`StockPort`, so the same three invariants are pinned a second time from this
side — in `catalog.int.test.ts::stock` and
`catalog.concurrency.int.test.ts::reserving the last unit` — against the
one-statement conditional UPDATE rather than through order creation. Neither set
is redundant: B1's says the order refuses, mine says the row never moves.

shelf (`is_show`)" was _thin_ there — the fixture only ever used a live product.

## Migration

Owner: **J** (legacy MySQL migration rows retired; the ETL rows below replace them)

MIG-001…017 describe the legacy in-place migration tool: a PHP command that
renamed retired tables inside the running MySQL database, deleted seeds, moved
settings between config tabs and could be rolled back. The rewrite does not
migrate in place. It reads the old database (read-only, never written) and loads
a **separate, new** PostgreSQL database, which is why none of those rows has a
successor test: there is no `apply` to be idempotent, no renamed table to drop
later, and no `rollback`, because rolling back is "point the load balancer at the
old stack, whose database was never touched".

What the old rows were protecting — that a migration is repeatable, that it
refuses rather than half-finishes, that it reports what it will remove before it
removes it — is protected by ETL-J-001…014 instead. Each is retired with the
reason in its own cell rather than deleted, so a reviewer can see where it went.
