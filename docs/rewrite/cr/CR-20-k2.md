## What

MUT-001 is now a script. From `next/`:

```
pnpm --filter @shop/guards mutations
```

It exports `HEAD` (`git archive`) into a scratch directory under the OS temp
directory. There it applies one mutation per protection, as a literal
search → replace that must match **exactly once**. It then runs the named
guarding tests from the copy's `packages/core`:

- **Baseline.** Every entry must run at least one test, and every one must pass.
- **Mutant.** At least one of those tests must fail.

It prints a table and exits non-zero if any of these happens:

- a mutant survives;
- a search string no longer matches;
- a baseline fails;
- a run selects nothing.

The live tree is never written. On this machine it takes about 60–150 s
(10 mutants plus the baseline), depending on how busy the host is. It needs
Docker, because the int tests start their own PostgreSQL 17 and Redis 7 through
the Testcontainers harness, exactly like `pnpm test:int`.

It should not gate pull requests. It is a check that the guarding tests still
guard, not a check of the change under review, and two to three minutes of
Testcontainers on every push is the wrong trade. It belongs next to
`concurrency-soak`: nightly and on demand.

## Ready to paste

Add the `mutations` job below under `jobs:` in `.github/workflows/next.yml`, next
to `concurrency-soak` (the `jobs:` line is shown only to fix the indentation). The workflow already has the `schedule` (`0 18 * * *`) and
`workflow_dispatch` triggers and `defaults.run.working-directory: next`, so the
job needs only the same `if:` guard. The setup steps are the soak job's, step
for step.

```yaml
jobs:
  # … existing jobs, then after concurrency-soak:
  mutations:
    name: mutation run (MUT-001, ten protections)
    # Nightly and on demand, like the soak: it asks whether the guarding tests
    # still guard, which is a question about the tree, not about the change.
    # Each of the ten protections is removed in a scratch copy of HEAD and its
    # named tests must fail; a survivor or a mutation string that no longer
    # matches exits non-zero (CR-20-k2).
    if: github.event_name == 'schedule' || github.event_name == 'workflow_dispatch'
    runs-on: ubuntu-latest
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v5

      - name: Enable corepack
        run: corepack enable

      - uses: actions/setup-node@v5
        with:
          node-version: 24
          cache: pnpm
          cache-dependency-path: next/pnpm-lock.yaml

      - name: Install
        run: corepack pnpm install --frozen-lockfile

      # The live tree's generated files are not what the copy uses (the runner
      # regenerates inside the copy), but guards imports @shop/contracts.
      - name: Generate aggregates
        run: corepack pnpm gen

      - name: Pre-pull the service images
        run: |
          docker pull postgres:17-alpine
          docker pull redis:7-alpine

      - name: Ten mutants
        run: corepack pnpm --filter @shop/guards mutations --json mutations.json

      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: mutation-report
          path: next/guards/mutations.json
          if-no-files-found: ignore
```

Notes for whoever pastes it:

- **Path of `--json`.** The path is resolved against the package directory,
  because `pnpm --filter` runs the script in `next/guards`. So the report lands
  in `next/guards/mutations.json`, which is what the upload step names.
- **Shallow checkout.** `actions/checkout@v5` checks out at depth 1. That is
  enough, because the runner uses `git archive HEAD`, which needs only the
  checked-out commit.
- **Timeout.** 45 minutes is a generous ceiling. The runner also has its own
  per-vitest-run timeout (`--timeout`, default 600 s), and a timeout counts as
  a kill that the table flags, not as a hang.
- **Local runs under a long `TMPDIR`.** Pass `--scratch /tmp/mut`. tsx's IPC
  socket path has a length limit, and a deeply nested temp directory exceeds it
  (`listen EINVAL`). CI's `/tmp` is fine.
