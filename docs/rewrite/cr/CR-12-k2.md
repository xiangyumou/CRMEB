# CR-12-k2 — a password-guessing run against the console leaves no record

**Stream:** K2 (hardening) **Status:** **RESOLVED** by R4 (wave 6; commit in `docs/rewrite/status/r4.md`) — `AdminAuthService.login(ctx, input, meta)` writes every outcome to `audit_logs` under `auth.adminLogin`; the route passes `requestMeta()` (`clientIp()` + user agent)
**Files:** `next/packages/core/src/auth/admin-auth.service.ts:74-113` (`login`: failures throw, nothing is written), `next/apps/web/app/admin-api/auth/login/route.ts` (`auth: 'public'`, so `handle()` writes no audit row)
**Pinned by:** `next/packages/core/src/auth/admin-login.trail.int.test.ts::K-SEC-A4 — what a password-guessing run leaves behind > leaves a readable trail of the failed attempts, without the password` (`it.fails`)

## What

AUDIT K-SEC-A4 recorded the gap and deferred it. Read again as the person
investigating an incident: five wrong passwords park the account for 15 minutes
(asserted: `parks the account after five misses` passes), and that is all. The
failure throws, the route is public so `handle()` writes no row (by design —
`handle.int.test.ts::does NOT audit the login itself — the body holds the password`),
and the lockout is a Redis counter that expires. "Was somebody trying our admin
passwords last week, from where, and did they get in afterwards?" has no answer
in `audit_logs`, and neither does the successful login that follows a run of
failures.

## Asked for

A dedicated write in `AdminAuthService.login` (or the route passing request
meta in) for each outcome — `success`, `invalid_credentials`, `locked`,
`disabled`, `captcha_failed` — with account, result, IP (see CR-14-k2 for which
IP) and user agent, **never the body**. `audit_logs` with a fixed `routeId`
(`auth.adminLogin`) is enough; `adminId` is null when the account is unknown.
The `audit_logs` reader already filters by account. Flip the `it.fails`.

## Until then

Only the pino log line exists; keep log retention long enough to answer the
question.
