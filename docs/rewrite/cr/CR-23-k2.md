# CR-23-k2: catalog's virtual-card claim is a second copy no shipping path reaches

**Stream:** K2 (hardening second pass, MUT-001) **Status:** RESOLVED 2026-09-23 by R1 (option 1): `catalog.service.ts::issueVirtualCard` and `catalog.repo.ts::claimVirtualCard` / `findCardForOrderItem` are deleted, with their tests (`catalog.int.test.ts`: "hands one card per order line…", "refuses when the pool is empty"; `catalog.concurrency.int.test.ts`: `claiming a virtual card`, 2). "voids only unclaimed cards" now claims its card by setting the row directly. The port table and the module comment in `catalog/index.ts` name `order.fulfil.repo.ts::claimVirtualCard` as the one claim. MUT-001's `virtual-card-claim` already mutated B2's copy; its comment now says it is the only one. `pnpm --filter @shop/guards mutations`: 10/10 killed. `CATALOG_CARD_POOL_EMPTY` stays registered in `contracts/src/catalog/errors.ts` (not R1's) but nothing throws it any more.
**Files:** `next/packages/core/src/catalog/catalog.service.ts` (`issueVirtualCard`), `next/packages/core/src/catalog/catalog.repo.ts` (`claimVirtualCard`), `next/packages/core/src/catalog/index.ts` (the port table that names B2 as its caller), `next/packages/core/src/order/order.fulfil.repo.ts` (`claimVirtualCard`, the one in use)

## What

There are two implementations of the virtual-card atomic claim, one of MUT-001's
ten protections:

- **`order.fulfil.repo.ts::claimVirtualCard`.** B2's copy. It is the one
  `order.fulfil.effects.ts` (`autoDeliver` on `order.paid`) calls. MUT-001
  mutates this copy: without `FOR UPDATE SKIP LOCKED` it is killed by
  `order.fulfil.concurrency.int.test.ts` "gives the last card to exactly one of
  two orders racing for it".
- **`catalog.repo.ts::claimVirtualCard`**, behind
  `catalog.service.ts::issueVirtualCard`, which `catalog/index.ts` exports as
  the port for "B2 … handing a card key to a paid order line". Its only callers
  are `catalog.int.test.ts` and `catalog.concurrency.int.test.ts`:

  ```
  $ grep -rn "issueVirtualCard" packages apps --include=*.ts | grep -v test
  packages/core/src/catalog/index.ts        (doc table, export)
  packages/core/src/catalog/catalog.service.ts:768 (definition)
  ```

So one claim is guarded, tested and shipped. The other is guarded and tested
but never shipped, and the catalog module's doc comment says B2 uses it when
B2 does not.

A future change could "fix" the catalog copy, see its tests pass, and believe
it had changed delivery.

## Proposal

Pick one:

1. **Delete the unused copy.** Remove `issueVirtualCard` and
   `catalog.repo.ts::claimVirtualCard` and their tests, and correct the port
   table in `catalog/index.ts`.
2. **Route through it instead.** Make `autoDeliver` call
   `catalog.issueVirtualCard` and delete B2's private copy.

Either way, keep one implementation and point MUT-001's `virtual-card-claim`
entry (`next/guards/scripts/mutations/mutations.ts`) at it.
