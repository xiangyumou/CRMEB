# CR-33-k2 — a draft menu WeChat refused shows its error nowhere

**Stream:** K2 (hardening second pass) **Status:** RESOLVED in `071c7e03e` (R3, wave 6)
**Found by:** `next/e2e/admin/specs/wechat-oa.spec.ts`, "WeChat refusing a new draft is shown on the page too" (`test.fail`)
**Files:** `next/apps/web/app/admin/(shell)/wechat-oa/menu/wechat-menus.tsx`,
`next/packages/core/src/wechat-oa/wechat-oa.menu.service.ts`

## What

`publish()` calls WeChat first and, on a refusal, writes the message to
`publish_error` on **the row that was being published** — "exactly what an
operator needs to read", as its comment says. The screen reads it from one
place only: the "上次发布失败" alert, fed by `GET /admin-api/wechat-menus/current`,
which returns the **live** menu. The list has no column for `publishError`.

So:

- republishing the live menu and being refused → the alert shows, with the
  errcode (the spec's second case proves this, and it passes);
- publishing a **new draft** and being refused — the common case, since WeChat
  validates URLs against the account's 业务域名 — → the draft's row holds the
  error, the live row does not, and the operator is left with a toast that
  disappears in three seconds. Reloading shows nothing.

A smaller half of the same thing: 发布's `ConfirmButton` invalidates
`wechatOaMenuList` and `wechatOaMenuCurrent` on **success** only, so even when
the live menu is refused the alert does not appear until the page is reloaded.
The spec's second case reloads before asserting, and says why.

## Asked for

Either one:

1. Show `publishError` on the row (a red `Tag`/`Tooltip` next to 草稿 in the
   状态 column) — the smallest change, no contract change; or
2. Have the alert read the most recent failed publish attempt rather than the
   live row (a contract change on `wechatOaMenuCurrent`, or a second route).

Option 1 is enough and keeps `/current` meaning "what followers see".
Either way, refetch on failure too (an `onError` that invalidates the same two
keys), so the error is on screen when the toast goes.

## Done when

The `test.fail` case starts passing (Playwright reports an unexpected pass)
and the `test.fail` line is deleted.

## Resolution (R3, `071c7e03e`)

The 自定义菜单 list shows 发布失败 and the WeChat error on the row that failed (`publishError`), and a refused publish re-reads the list and `current` (`onError` refresh) so the alert shows without a reload. Unit: two tests in `wechat-menus.test.tsx`; e2e: `wechat-oa.spec.ts`'s `test.fail` removed and the row assertions added.
