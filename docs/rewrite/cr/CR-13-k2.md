# CR-13-k2 — every write on the staff console calls `ctx.audit` and nothing is recorded

**Stream:** K2 (hardening) **Status:** OPEN — for the orchestrator / P0-A (`handle()` + audit repo)
**Files:** `next/apps/web/src/server/handle.ts:414` (`if (surface === 'admin' && actor.kind === 'admin' && MUTATING…)`), every `next/apps/web/app/api/v1/staff/**/route.ts` that calls `ctx.audit(…)`

## What

`handle()` writes an `audit_logs` row only for the admin surface and an admin
actor. The staff routes (`auth: 'staff'`, actor kind `staff`) call
`ctx.audit(target)` like the admin ones — `staff/coupon-grants`,
`staff/products` (create, visibility, SKU price and stock, label and category
batches), `staff/users/:uid/group|labels`, `staff/orders/:id/price|address|remark|shipments`,
`staff/refunds/:id/review|remark` — and the call is a no-op. So a 店员 who
reprices a SKU to ¥0.01, ships an order to a new address, or grants themselves a
coupon (CR-10-k2) leaves no row anywhere an operator can read. `pnpm guards`'
`route-hygiene` check is satisfied by the `ctx.audit` call, so nothing flags it.

A2 knew, and recorded it as a decision in
`apps/web/app/api/v1/staff/products/catalog-staff.int.test.ts:299-304`: "the
trail for the phone is the order/product history, not the console's log". That
holds for orders (`order_status_logs`). There is no product history table, and
none for coupon grants or user labels, so for those the decision leaves no trail
at all. The `expect(auditLogs).toHaveLength(0)` assertions in that file (lines
270, 304, 321, 444) are what this CR would flip.

This is route-level (`apps/web`), outside K2 §1's test grant; no test is
committed. The assertion wanted is one `handle.int.test.ts` case: a staff
`PUT /api/v1/staff/products/:id/skus` writes one `audit_logs` row naming the
staff user and `product:<id>`.

## Asked for

Write the row for `surface === 'staff'` too. `audit_logs.admin_id` is an admin
foreign key, so either add an `actor_kind` + `user_id` pair (migration) or a
separate `staff_audit_logs` table with the same reader; the admin 操作日志
screen should list both. Redaction and the size cap are the same.

## Until then

Staff writes are traceable only through the domain rows they leave
(`order_status_logs` for orders; nothing for products, coupons or user labels).
