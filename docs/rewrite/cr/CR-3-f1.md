# CR-3-f1 — the config-group bucket, the patch CR-2-c asked for

- **Stream:** F1 (system & storage)
- **Status:** worked around by an explicit import list; patch below is ready to apply
- **Affects:** `next/packages/core/scripts/gen-config-groups.ts` (new),
  `next/packages/core/package.json` (orchestrator-owned), `.gitignore`
- **Settles:** CR-2-c ("config groups live at `core/src/<domain>/<group>.config.ts`,
  registered from the domain's own `index.ts`") — the convention is decided; only
  the aggregation is missing.

## What is wrong

`defineConfigGroup` registers a group **as a side effect of its module being
imported**. `GET /admin-api/system/config-groups` therefore lists whatever
happens to have been imported by the time the request is served, which in
practice means: whatever some shared file imported.

`@shop/core` has no `gen` script at all, so unlike `menu.gen.ts` (web) and
`jobs.gen.ts` (worker) there is nothing to collect the `*.config.ts` files.

## Why it matters

Every stream that ships a settings screen has to edit one shared file, which is
exactly the merge conflict the generated buckets exist to prevent. It also
fails quietly in the direction nobody checks: forget the import line and the
group simply is not on the settings index, with no error anywhere. B1's `order`
group arrived on `rewrite/integration` this way and was invisible until F1
added the import by hand.

## Suggested fix — `packages/core/scripts/gen-config-groups.ts`

Same shape as `apps/worker/scripts/gen.ts`:

```ts
/**
 * Aggregates every `src/<domain>/*.config.ts` into the gitignored
 * `src/config-groups.gen.ts`, so a domain adds a settings screen by adding one
 * file and nothing shared is edited.
 *
 * Run: `pnpm --filter @shop/core gen`
 */
import { glob, writeFile } from 'node:fs/promises';
import path from 'node:path';

const srcDir = path.resolve(import.meta.dirname, '..', 'src');

const files: string[] = [];
for await (const entry of glob('*/*.config.ts', { cwd: srcDir })) {
  const name = entry.split(path.sep).join('/');
  if (name.endsWith('.test.ts')) continue;
  files.push(name);
}
files.sort();

const lines = [
  '// Generated by `pnpm gen` (packages/core/scripts/gen-config-groups.ts).',
  '// Do not edit, do not commit.',
  '/* eslint-disable */',
  ...files.map((file) => `import './${file.replace(/\.ts$/, '')}';`),
  '',
  `/** ${files.length} config group file(s), imported for their registration side effect. */`,
  'export const CONFIG_GROUP_FILES = [',
  ...files.map((file) => `  '${file}',`),
  '] as const;',
  '',
];

await writeFile(path.join(srcDir, 'config-groups.gen.ts'), lines.join('\n'), 'utf8');
console.log(`core: aggregated ${files.length} config group file(s)`);
```

`packages/core/package.json`:

```json
  "scripts": {
    "gen": "tsx scripts/gen-config-groups.ts",
    "typecheck": "tsc -p tsconfig.json",
```

with `tsx` added to `devDependencies` (the web and worker packages already have
it; F1 must not commit `pnpm-lock.yaml`, which is why this is a CR and not a
commit).

`turbo.json` needs no change — `gen` already outputs `src/**/*.gen.ts` and every
other task depends on it.

## Migration when it lands

1. `packages/core/src/system/config.service.ts` imports `'../config-groups.gen'`
   instead of `'./config-groups'`.
2. Delete the import list in `packages/core/src/system/config-groups.ts`, keeping
   only the `defineConfigFieldExtras('storage', …)` call (which CR-1-f1 removes
   in turn), or delete the file outright once both CRs have landed.
3. Nothing else: group registration, the descriptor endpoint and every test are
   unchanged, because they all read `allConfigGroups()`.

## Local workaround in place

`packages/core/src/system/config-groups.ts` is an explicit import list with a
comment saying so. It currently loads eight `system` groups, `storage` through
its domain index, and `order` through `../order/index`. Any stream adding a
group before this CR lands adds one import line there — and should, because
until then a group nobody imports does not exist.
