# CR-11-k2 — two public-ish writes with no per-caller ceiling: the visit beacon and 小程序码

**Stream:** K2 (hardening) **Status:** RESOLVED in `79a42fce4` (R3, wave 6)
**Files:** `next/packages/core/src/user/user.visit.service.ts:71-90` (throttle key `visit:${subject}:${body.path}`), `next/packages/core/src/wechat/wechat.mini-code.service.ts:55-125` (`miniCodeUrl`: no budget on uncached pairs)
**Pinned by:** `next/packages/core/src/user/user.visit.budget.int.test.ts::K-SEC-V1 — what one anonymous address can write > cannot write more than a browsing session’s worth of rows in a minute`; `next/packages/core/src/wechat/wechat.mini-code.budget.int.test.ts::K-SEC-M1 — how many new codes one shopper can mint > stops minting new codes for one account well before a hundred in an hour` (both `it.fails`)

## What

**`POST /api/v1/visits`** (`auth: 'public'`). The throttle is one row per
subject **per path** per minute, and the path is the caller's: any `/…` up to
255 characters. Varying it defeats the throttle, so a loop inserts one
`user_visits` row per request — table growth without bound, and 浏览量 on the
dashboard set by whoever runs the loop. The pinned test writes 200 rows in one
minute from one address. (访客数 is separately inflatable by varying the
address — CR-14-k2.)

**`GET /api/v1/wechat/mini-qrcodes`** (`auth: 'user'`, any free account). A
cached `(page, scene)` is free; a new scene (any ≤ 32 bytes) always costs a
`wxa/getwxacodeunlimit` call, a PNG in the storage root and a
`wechat_mini_codes` row. Nothing counts per account, so one account grows the
uploads volume and spends the mini program's API rate at will. The pinned test
mints 100.

## Asked for

- Visits: keep the per-path window and add a per-subject ceiling across paths
  (60 rows a minute is generous for a person); over it, drop silently as today.
- Mini codes: a per-user `fixedWindow` on **uncached** pairs only (30 an hour is
  generous: a poster page asks once per product) → `RATE_LIMITED`; cached pairs
  stay free.
- Flip both `it.fails`.

## Until then

The edge has no `limit_req` either (CR-13-k's territory), so nothing upstream
catches it.

## Resolution (R3, `79a42fce4`)

Visit beacon: a second fixed window per subject (60 per window, `visit:<subject>`) after the per-path one; over it the visit is dropped silently. 小程序码 mint: 30 per hour per user/staff actor (`wechat:mini-code:mint:u:<id>`), `RATE_LIMITED` (in the contract), spent after the configured check and before the WeChat call. Both K2 pins flipped; four + three tests added.
