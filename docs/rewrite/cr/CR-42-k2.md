# CR-42-k2 — the DIY home page is read whole from PostgreSQL on every request, and it is the top statement by time

**Stream:** K2 (hardening second pass, §4 load smoke) **Status:** OPEN — for stream G (DIY), low priority
**Files:** `next/packages/core/src/diy/diy-page.service.ts` (`getHomePage`, ~l. 358), `next/packages/core/src/diy/diy.repo.ts` (`findHomePage`, ~l. 76), `next/packages/core/src/diy/diy.cache.ts` (the cache 底部导航 and 个人中心 already use, CR-3-h2)
**Evidence:** `next/load/REPORT.md` (run A and run B)

## What

`GET /api/v1/diy/pages/home` is the first request every app launch makes. Each
time, it runs:

```sql
select "id", "name", "kind", "title", "status", "is_home", "content", "schema_version", "background",
       "published_at", "created_at", "updated_at", "deleted_at"
  from "diy_pages" where ("diy_pages"."is_home" = $1 and "diy_pages"."deleted_at" is null) limit $2
```

That reads the page's full `content` jsonb. For the production home page seeded
here (`prod-8.json`) that is about 90 KB. Then it runs `cleanDiyData` over it and
serialises it again. The response carries a weak `ETag`, but the handler has
already read and cleaned the row before it can compare, so an unchanged page
costs the same as a changed one.

| Run | calls (= home requests) | total ms | mean ms | rank by total time        |
| --- | ----------------------: | -------: | ------: | ------------------------- |
| A   |                    2286 |   1378.2 |   0.603 | **1st** of 103 statements |
| B   |                    1526 |   1217.2 |   0.798 | **1st** of 107 statements |

Latency is fine (p50 15.7 ms / p95 29.7 ms in run A). This is not a defect. It
is the single largest slice of database time in the storefront mix, for a
document that changes when an operator presses 发布.

## Asked for

Cache the cleaned storefront payload of the home page in Redis under the same
`DIY_CACHE` namespace that `invalidateDiyStorefrontCache` already clears. Every
write path (`savePageContent`, `publishPage`, `setHomePage`, `updatePage`,
`restorePageDefault`) already calls it, so no new invalidation is needed. Serve
`If-None-Match` from the cached version without touching the row.

Mirror the 个人中心 cache tests already in `diy.int.test.ts` ("caches for 60 s
and drops the entry the moment an operator publishes", "drops the 个人中心
entry on a save, a publish and a delete alike") for the home page. The admin
e2e `diy.spec.ts` pins read-after-publish over HTTP as well.
