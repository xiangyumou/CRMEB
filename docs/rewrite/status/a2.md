## 1. The ten staff routes (CR-4-h2, accepted in full)

All under `/api/v1/staff/`, all `auth: 'staff'`, all `tags: ['catalog']`. No
permission atom: staff is B2's `orderStaff` config list, not a role — a shopper
is on it or gets a 403. Every handler is a thin `handle(route, fn)` over a

Request bodies H3 also needs:

- ② `{ visible: boolean }` — not the console's `{ status }`. The switch has two
  positions and a staff member has no way to make a draft.
- ⑤ `{ productIds: string[1..100], labelIds: string[0..20] }`. The labels
  **replace** what each product carried; an empty array clears them.
- ⑥ `{ productIds: string[1..100], categoryIds: string[1..20] }` — **plural**,
  see decision 3.
- ⑧ `{ items: [{ id, price?, cost?, originalPrice?, stock?, skuCode?, weight?,
  volume? }] }`, 1..200 rows, no duplicate `id`, at least one editable field per
  row (`修改内容至少填写一项`).
- ⑩ `{ name, imageUrl, sliderImages[≤9], categoryIds[1..20], unitName,
  descriptionHtml, visible, freightMode, fixedFreight?, shippingTemplateId?,
  sku: { price, cost?, originalPrice?, stock, skuCode?, barCode?, weight?,
  volume? } }`. Single-spec only, no `logistics` (decision 4).

Error codes the phone can see: `CATALOG_PRODUCT_NOT_FOUND` (404),
`CATALOG_SKU_NOT_FOUND` (404), `CATALOG_LABEL_NOT_FOUND` (404),
`CATALOG_CATEGORY_NOT_FOUND` (404), `CATALOG_NAME_TAKEN` (409),
`CATALOG_PRODUCT_SPU_TAKEN` (409), `CATALOG_CARD_STOCK_NOT_EDITABLE` (422, new).

### Decisions

1. **`low-stock` reads `catalogConfig.stockWarningThreshold`**, the key N1 wired
   to `admin_low_stock` — not `trade.stockWarningThreshold`. The badge on the
   phone and the 库存预警 screen in the console are the same number or they are
   a bug.
2. **`in-stock` (仓库中) covers `draft` as well as `off_shelf`.** Legacy had one
   `is_show`; the rewrite splits "never published" from "taken down", and a
   draft reachable only from 全部 would be a product the phone can see and never
   act on. Added a repo-internal `not_on_shelf` tab for it; the admin contract's
   tab enum is untouched.
3. **`categoryIds` plural, deviating from the CR's singular `categoryId`.** The
   frozen schema has `product_categories_map` (many-to-many) and the drawer
   collects a checkbox list. One name for one thing.
4. **添加商品 is single-spec and carries no `logistics`.** A spec matrix cannot
   be built on a phone and legacy never tried; 门店自提 is retired shop-wide, so
   the field is absent rather than accepted and ignored. The service builds a
   full `AdminProductForm` and calls `adminProductCreate` — same validation,
   same SPU check, same category check as the console.
5. **The SKU PUT is a patch, and takes row locks.** Legacy's `postUpdateAttrs`
   rewrote the whole `eb_store_product_attr_value` row, so editing a price from
   a screen loaded two minutes ago wrote back that screen's stock and silently
   un-sold every order placed in between. Here an absent key is left alone, and
   a stock change happens under `SELECT … FOR UPDATE` over the product's SKUs in
   ascending id order with the `products.stock` rollup in the same transaction,
   so an order's reservation serialises with the edit instead of interleaving.
   Three races in `catalog.concurrency.int.test.ts` pin it.
6. **A card-key SKU refuses a stock edit** (`CATALOG_CARD_STOCK_NOT_EDITABLE`,
   new): the card pool *is* the stock. A price edit on the same SKU is allowed,
   and a test says so.
7. **Staff writes leave no `audit_logs` row.** `audit_logs.admin_id` is an admin
   FK and `handle` only audits the admin surface. The route files still call
   `ctx.audit(...)` — the same no-op B2's staff routes make — so the target is
   right the day the log grows a second actor kind. The HTTP test pins the empty
   table so nobody reads it as the guard having been skipped.

## 2. 运费模板 is a select

`shippingTemplateId` on the admin product form was a free text box carrying
"运费模板选择器待 B2 流上线后替换" (A's decision 11). F2 shipped
`GET /admin-api/shipping/template-options`, so it is now a `select` fed by that
route through the generated client, options labelled `名称（计费方式）` —
two templates can share a name and charge by 件 versus by 重量, and from the
product form there is otherwise nothing to tell them apart.

固定运费 gained the help text it always needed: **the amount is charged per
unit** (legacy `postage × cart_num`), not once per order. `product-editor.test.tsx`
stubs the options route and pins the whole switch.

A's decision 11 is closed. Decision 12 (pickers as `mode: 'tags'`) is closed for
the two activity forms, see below; 推荐商品 / 赠送优惠券 on the product form
still take typed ids and are not in this brief.

## 3. `<SkuPicker>` in the kit

`apps/web/src/admin/kit/sku-picker.tsx`, exported from `kit/index.ts`. Search
products by keyword, expand a row to its SKUs, tick them, receive
`{ productId, skuId, specText, price, stock }[]`.

Kit primitives and the generated contracts client only — it reads A's own
`/admin-api/catalog/products` and `/admin-api/catalog/products/:id`, so the rows
it offers are the product page's rows and there is no second definition of "a
sellable SKU" to drift. No `@shop/core` import.

`productId` narrows it to one product and hides the search box. Both activity
forms pass their own: a group buy on product 12 cannot price a SKU of product
13, and `GROUPBUY_SKU_NOT_IN_ACTIVITY` / `PRESALE_SKU_NOT_IN_ACTIVITY` would
only say so after the form was filled in and submitted.

Wired into `groupbuy-enums.tsx` and `presale-enums.tsx` in place of the bare
规格 ID inputs. **Submit bodies are unchanged** — the row still carries
`skuId, price, stock, quota, isEnabled`. The id box stays visible and editable
on purpose: a migrated activity can name a SKU whose product has left the shelf,
and the picker lists on-shelf products, so a read-only field would make that row
uneditable. D's and D2's form tests are untouched and green.

`sku-picker.test.tsx` covers search → expand → select (three cases: multi-select
returns both rows with their product id, `multiple={false}` keeps one, `value`
pre-ticks).
