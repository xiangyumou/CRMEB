## Decisions

1. **`panels/_fields/` holds G2's composites, per CR-1-g2.** Eight legacy
   widgets have no counterpart in G1's frozen barrel and the rest
   (`c_common_style`, `c_data_style`, `c_icon_style`) are compositions of
   editors that do. Nothing in `fields/` is forked or touched.
2. **`zIndexConfig` (组件上浮) gets no control.** `c_common_style.vue:5` has the
   row commented out, so the legacy admin could not edit it either. The key is
   left untouched in the node.
3. **超级组件's inner designer is not built; see CR-2-g2.** `c_custom_btn` opens
   `CustomDesign/`, a second drag-and-drop editor writing `customComponents`.
   The panel ships every other row and carries `customComponents` through
   untouched. No stream owns that designer.
4. **`c_data_style` is the same renderer as `c_common_style`.** Rather than a
   second copy, `_fields/common-style.tsx` takes a key map and exports both
   `DiyCommonStyleSection` and `DiyDataStyleSection`.
5. **Icon classes are typed, not picked.** `c_menu_list` opens an iconfont
   picker for `list[].icon`; the new admin has no iconfont, so the class name is
   a text input. The stored value is identical.
6. **No panel writes a key the node does not already carry.** Sixteen legacy
   panels inject missing keys on open (`patchConfig` / `defaultConfig`), so in
   the old admin opening a page and saving it changed the stored JSON. Panels
   here draw a row only when its group is present, exactly like the legacy
   `v-if`s, which is what keeps the fixture round-trip test meaningful. The
   keys that are therefore unreachable on a factory-default node belong in the
   factory defaults: **CR-3-g2**, whose worst case is `member` (46 keys).
7. **`c_member.vue`'s colour-swapping watcher is not reproduced.** Changing the
   layout to 样式四/样式五 rewrites six stored colours between `#fff` and `#333`.
   It destroys colours the operator picked; the panel writes the layout only.
