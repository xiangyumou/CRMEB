## Decisions taken (no question asked, per the brief)

### Freight

1. **Fixed postage is charged per unit**, i.e. legacy `postage × cart_num`
   (`OrderFreightCalculator::getOrderPriceGroup`). B1's stand-in
   `fallbackFreightQuote` charges it _once per product_, which is a different
   number for any cart with quantity > 1. F2's real `FreightPort` restores the
   legacy behaviour — see "B1 expectations that change" below.
2. **The legacy first-unit bug is fixed, not ported.** Legacy: if
   `number > first` and `continue <= 0`, postage is **0** — a bigger cart costs
   less than a small one. F2 charges `firstPrice` in that case.
3. **Shop-wide 满额包邮** (`store_free_postage`, now F1's
   `tradeConfig.freeShippingThreshold`) zeroes the _whole_ order's postage,
   fixed lines included, exactly as legacy did.
4. Free rules need **both** thresholds met (`minUnits` and `minAmount`, a null
   one counting as satisfied), and the whole template group drops out.
5. The "max first price" arrangement is ported as-is: one group pays
   first + continuation, the others pay continuation only, and the answer is the
   maximum over those arrangements.

### Logistics

6. **F1's `logisticsConfig` is reused; no second config group.** F2 registers a
   `LogisticsPort` driven by it.
7. `provider: 'kuaidi100'` has **no driver in scope**. It is treated as
   unavailable with a logged warning; CR filed asking F1 to drop the enum value.
8. The Aliyun market host is hardcoded, never a config value, the fetch has a
   timeout, and the client is tested against a fake. No real endpoint is called.

### Cities

9. `cities` is immutable seed data: **no write routes, no cache-bust route**
   (the legacy `city/clean_cache` existed only because the writes did). The
   response carries a `version` fingerprint served as a weak `ETag` plus
   `Cache-Control`. No 304 short-circuit — `Ctx` exposes no request headers.

### CMS

10. Storefront lists and detail filter `status = 'published'`; the legacy
    storefront leaked drafts.
11. HTML is sanitised **on write** against an allow-list — no `script`, no
    event attributes, no `javascript:` URLs. Legacy `htmlspecialchars`-then-
    decode netted zero sanitisation.
12. `views` is incremented with an atomic `UPDATE … SET views = views + 1
RETURNING views`; legacy read-modify-wrote a varchar.
13. The category tree is capped at 2 levels, as the legacy admin was.
14. `cms/relation/:id` and `cms/unrelation/:id` have no successor — the linked
    product is a field on the article form.

### Statistics — handed to F3, kept here as research

15. **One definition per figure**, written down in
    `packages/core/src/stats/DEFINITIONS.md`. The legacy pages disagreed with
    each other in nine documented places (revenue by `pay_time` on one page and
    `add_time` on another, four different refund definitions, a lowercase
    `'timekey'` bug on the dashboard).
16. Revenue = `sum(orders.paid_amount - orders.refunded_amount)` bucketed by
    `orders.paid_at` in **Asia/Shanghai** days.
17. Refund figures read `refunds.status = 'succeeded'` / `succeeded_at`.
18. Retired with their features: balance, recharge, commission, points,
    membership, 资金流水/账单记录, 余额统计, the WeChat-subscribe block, and the
    four legacy `home/*` dashboard endpoints (F1's dashboard replaces them —
    F2 contributes tiles through `registerDashboardContributor`).
19. Money in a statistics response is a **number with a `format` field**, not a
    `money` string, matching F1's frozen `dashboardTile`. Charts need numbers.

### Permissions

20. New atoms: `shipping:template:{read,write,delete}`,
    `shipping:express:{read,write}`, `cms:article:{read,write,delete}`,
    `cms:category:write`, `stats:{user,product,trade,order}:read`,
    `stats:{product,trade}:export`. The 快递公司 _picker_ deliberately keeps
    `order:order:read` so a shipping operator needs no second grant.

## B1 expectations that change once `shipping` is registered

B1's own unit test of the stand-in (`order.pricing.test.ts::fallbackFreightQuote`)
keeps passing — it calls the fallback function directly and the fallback is not
being changed. What changes is what the **application** quotes, because
`handle()` imports `@shop/core/domains`, which now registers F2's `FreightPort`:

| Test                                                                                                                 | Fixture                                         | Was                                              | Becomes                                                           |
| -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------- |
| `core/src/order/order.int.test.ts` — "prices the ticked cart rows with freight and a coupon"                         | `freight: '8.00'`, quantity 2, no 运费模板      | `freightAmount '8.00'`, `payableAmount '118.00'` | `'16.00'` / `'126.00'`                                            |
| `core/src/order/order.int.test.ts` — "creates the order, takes the stock, empties the cart and schedules the cancel" | same fixture, `expectedPayableAmount: '118.00'` | `payableAmount '118.00'`                         | `'126.00'` (the `expectedPayableAmount` argument has to move too) |
| any other case built by `makeProduct({ freight: … })` with quantity > 1                                              |                                                 | `freight × 1`                                    | `freight × quantity`                                              |

Cases with quantity 1, `freightMode: 'free'`, or no address (freight quoted as
zero because the address is unknown) are unaffected — that includes every
`checkout.int.test.ts` case in `apps/web`.

Those two files are B1's, not F2's. Two ways to land it, orchestrator's call:
either B1 updates the numbers, or the tests keep using the fallback (they do not
import `@shop/core/shipping`, so left alone they stay green and simply no longer
describe production).

## CMS

`packages/core/src/cms/` is five files: `cms.sanitize.ts` (the allow-list
sanitiser, 23 unit cases), `cms.repo.ts`, `cms.category.service.ts`,
`cms.article.service.ts` and `index.ts`, plus `cms.int.test.ts` (13 cases).
Importing `@shop/core/cms` registers **nothing** — unlike `shipping`, this
domain installs no port.

| Decision | Why |
| --- | --- |
| The sanitiser is hand-written, not a dependency | The input is one editor's output and the allow-list is 33 tags; a general HTML parser is a bigger attack surface than 230 lines, and adding a package to `packages/core` is a lockfile change this branch may not commit. |
| The tag scanner is quote-aware, and a bare `<` is text | `<a href="data:text/html,<script>…">` is one tag, and an operator typing `5 < 6` gets `5 &lt; 6` rather than losing the rest of the sentence. |
| Deleting an article releases its slug | `articles_slug_uq` covers deleted rows too, so a soft-deleted article would otherwise squat on a URL that nothing in the admin can show the operator. |
| `publishedAt` is stamped once | Un-hiding an article must not re-date it to the top of the storefront list. `articles_published_shape` still holds: a published row always carries a timestamp. |
| The related product is read through `productCardsFor` | An article pointing at an off-shelf product renders `product: null` instead of advertising something nobody can buy. |
| A hidden parent category hides its children | The legacy navigation left orphaned sub-tabs pointing at an empty list. |
| The category list is unpaged and flat | The server computes `depth`; the page indents by it and never rebuilds the tree. |

### What the DIY editor needs from CMS

`apps/web/src/admin/cms/link-targets.ts` exports `articleLinkTargets`,
`articleCategoryLinkTargets` and a ready-made `cmsLinkTargets(next?)` callback
for G1's `createDiyLinkSource({ targets })` (published articles only, uni-app
paths). **Nothing installs it yet**: no file in the tree calls
`createDiyLinkSource`, so whoever wires the DIY shell composes this with the
catalog's equivalent. That wiring is one line and is not in F2's paths.

### ETL

`packages/etl/src/mappers/{shipping,cms}.ts` + tests, and the two `export * as`
lines in `packages/etl/src/index.ts`. `mapCms` takes the sanitiser as an
**injected callback** (`sanitize`) rather than importing `@shop/core/cms`, which
would add a workspace dependency to `@shop/etl` — the runner (stream J) passes
`sanitizeHtml`, and the report counts every body migrated without it. Cities and
the 1101 carriers stay seed data; the shipping mapper emits only the courier
`sortOrder`/`isEnabled` an operator changed.
