## 5. The web unit flake

**Symptom.** Four streams saw `ReferenceError: window is not defined`, each
time from a different admin component test file. It only happened under
`turbo run … test:unit build`.

**Root cause.** The unit suite runs under happy-dom, but vitest only lifts the
DOM names onto the global. `setTimeout`, `setInterval` and `setImmediate` stay
Node's. Every component file ends with Node timers still pending. These come
from antd motion and debounce timers and from React's scheduler, which drives
itself through `setImmediate` (captured at import). K2 counted them per file:
`diy/panels` 163, `zod-form` 19, `product-editor` 12, `customers` 11, and at
least 3 in each of the 41 files. Vitest tears the environment down (happy-dom
`abort()`, then deletes `window`, `document` and the rest) in the worker's
stop path, while its `uncaughtException` listener is still installed. A
leftover callback that fires after that and reaches a React state update calls
`resolveUpdatePriority()`. That reads `window.event` and throws exactly this
error. If it lands before the worker reports `stopped`, the file fails. On an
idle machine the stop path wins. When `next build` is competing for the CPU,
it sometimes does not.

**Evidence.** Before the fix, K2 ran `turbo run test:unit build` 10 times and
the predecessor ran it 18 times: 0 of 28 reproduced it on this machine. So the
proof is mechanical. A diagnostic setup file recorded the leftover handles for
each file, and a forced callback after teardown throws the reported error.

**Fix** (`95c72e456`). `apps/web/src/test/timers.ts` is listed **first** in
`setupFiles`, so it runs before React's scheduler captures `setImmediate`. It
hands out tracked timers, cancels every one still pending after the file's
last hook, and refuses to run a callback once `window` is gone.
`vi.useFakeTimers()` still works. After the fix: **10 of 10** turbo
`test:unit build` runs clean, 41 files and 663 tests each.

**Out of grant.** The brief's §5 grant is `apps/web/vitest.config.ts`.
`timers.ts` is a new test-support file beside the existing
`src/test/setup.ts`. It is test code, not production code, but it is outside
the literal grant. The orchestrator should accept it or move it at merge.
