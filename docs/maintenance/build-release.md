# Coordinated builds and release checks

The checked-in `crmeb/public` output predates this maintenance pass. A backend image alone does not update the separately mounted production public directory.

Admin: `sh scripts/build-admin.sh /absolute/path/to/admin-artifact`. The script uses `npm ci` and builds outside `crmeb/public`; its default output is `template/admin/dist`. The existing `/admin` public URL does not change. `template/admin/.nvmrc` pins Node 20.19.0; npm 10.8.2. A clean `npm ci` and production build passed in an isolated Node 20.19.0 container. Existing CSS order/bundle warnings remain; they did not fail the build.

H5 and MP-WEIXIN: open `template/uni-app` in HBuilderX and build release outputs for H5 and WeChat mini-program separately. The exact HBuilderX version, platform-specific options, output paths, and real device results are **not verified**; record them after both builds succeed. Syntax checks alone do not qualify a release.

After building, place a release manifest outside the checked-in `public` directory. The format is JSON with `releaseVersion` (for example `v1.2.3`), full 40-character `gitCommit`, and `backendImageDigest` (`sha256:` followed by 64 lowercase hex digits). Each of `admin`, `h5`, and `mpWeixin` contains the same `gitCommit`, nonempty `toolVersion`, `artifactPath` relative to the manifest (or absolute), and lowercase 64-character `artifactSha256`. `artifactPath` may be a file or directory; for a directory, the digest is SHA-256 of sorted lines `relative/path\0sha256(file)\n`. Preserve the mini-program build package submitted for review as the MP-WEIXIN artifact. Run `node scripts/verify-release.cjs /absolute/path/release.json`. A missing output, differing commit, invalid field or checksum mismatch fails.

For release, coordinate an admin build, H5 build, mini-program review/version, backend image and the same source commit. Back up the mounted public files and configuration; migrate the database only on a verified copy following `crmeb/upgrade/core-store/README.md`. Update the separately mounted admin/H5 resources with the paired artifacts, roll out the backend, restart queues and scheduled tasks, clear application caches and test orders, group buying, presale and QR contact. Allow for old mini-program versions and client caches. Rollback restores the previous backend and public artifacts together; restore database only when the migration rollback's conflict checks pass. No production release or actual WeChat gateway verification has been performed here.

Admin 404 staging checklist: identify the failed request's URL, HTTP method, response content type and initiator in the browser network panel. `/adminapi/...` is an API request; `/admin/system_static/...` is an asset; `/notice` is order notifications (WebSocket); `/msg` is retired chat. Compare the deployed HTML's referenced JS/CSS with the files present in `${CRMEB_PUBLIC_DIR}/admin/system_static/` (the directory is independently mounted in `deploy/production/compose.yml`). Validate that `/admin/index.html` and deep-link HTML responses carry `Cache-Control: no-cache, must-revalidate`; hashed JS/CSS can retain the existing 12-hour cache. Publish new hashed files *before* the HTML, keep the prior release's hashed files available until open browser sessions have expired, then garbage-collect them in a separate release. Test existing open tabs and hard reload during staging deployment and rollback. Do not claim staging cache behavior is verified until it has been exercised behind the actual proxy.
